# Research file format (every topic file follows this)

Folder: `research/` in the Piano Lessons app repo. The app: an Android tablet learning app for one 6-year-old in UK Year 2 (piano play-along, maths, handwriting, colouring, "bigger or smaller"). He has a **short focus window**. Next feature: **basic-concept mini-games** (darker/lighter, closer/further, bigger/smaller, above/below, high/low…) that **pop up during piano play** and at random spots across the app: 2–3 quick questions, then back to the activity.

The repo is PUBLIC: summarise in your own words, quotes under 25 words, no copied tables or images. Never name the child.

```markdown
# NN — Title
Last updated: YYYY-MM-DD · Researcher: subagent · Keywords: comma, separated, words, for, search

## Answer in 5 lines
The bottom line for the app.

## Findings
### F1. One-line claim  `evidence: strong | moderate | weak | expert opinion`
2–6 lines: what was found, who, sample, ages, effect size where given. Cite as [S3].
### F2. ...

## Design rules for the app
- R1. Concrete rule we can build (links to F#).

## Open questions / conflicting evidence

## Sources
- [S1] Author(s), year. *Title.* Publisher/journal. URL. — one line on what it supports. (type: RCT / meta-analysis / review / guideline / clinical guide / textbook / practitioner)
```

Rules: cite only sources you actually opened or whose abstract you read; prefer peer-reviewed, systematic reviews, NHS/RCSLT/NICE, DfE/NCETM, AAP/WHO/RCPCH, Pearson test manuals; mark commercial blogs as weak. Give age ranges whenever a source has them.
